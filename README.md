# Project-Wisdom DerpFest 17 compatibility patches

These patches record the **17 modified upstream projects** for the Samsung SM-P205 (`wisdom`) Android 17 / DerpFest build. The legacy fscrypt keyring and logon key masks now preserve owner `SETATTR` (`0x082d0000`), which init needs when it reapplies the keyring permissions during boot. The 2026-09-29 build with this correction booted twice on the device, and FBE canary hashes survived a dirty flash and PIN unlock. Full release hardware testing remains pending. The `build/soong` patch ignores the NDK-only `Android.mk` files in libjxl's sjpeg submodule, which otherwise stop Android 17 product configuration after recursive submodule sync. The 2026-10-05 update also packages the official Monet light/dark animations under `/system/media`, installs Fossify Gallery under `/system/app`, retains Gallery2, adds dark animation fallback support, and uses the dark animation by default on Wisdom while preserving the authored aspect ratio (1080×2160 → 960×1920 on the 1200×1920 portrait panel). Project-Wisdom-owned device, kernel and vendor changes belong in their own source repositories and are intentionally excluded. OTA ZIPs, device logs and user data are also excluded.

Each patch is a binary-safe `git diff` from the exact `base_commit` in `manifest.json`. The manifest records the upstream URL, SHA-256 and file count. Applying a patch requires that project's HEAD to match its recorded base and its worktree to be clean. Apply Project-Wisdom-owned source repositories through their normal branches first.

The patch set was reviewed and rebased against the 2026-10-05 DerpFest manifest `04cf624bec963ac042c1487f1b529f5f5ad44203`. Four upstream project HEADs moved; the original 16 patches passed the full preflight and were applied to the active source tree. The `system/core` patch now removes the stale `ro.crypto.state` spoof from the updated upstream function while retaining the new upstream verified-boot implementation. The `vendor/lineage` patch preserves the upstream certification include and the Wisdom product's opt-out switches, and now contains the system-location rules for Monet animations and Fossify Gallery. The additional `frameworks/base` patch selects the system dark animation when the dark theme is active. All 17 patch checksums and clean-base application/reversal tree comparisons pass and reproduce the active upstream source changes, including the later dark-default and proportional-animation fixes. The 2026-10-05 Wisdom `m derp -j8` build and Recovery sideload succeeded. Boot, root, OpenEUICC startup, and portrait single/landscape split shade were verified; full hardware regression remains pending. See [the validation and source record](docs/validation-20261005.md) for the matching Project-Wisdom source revisions and test boundaries. The QS orientation override belongs to the device repository, and the xxKSU v5 adaptation belongs to the kernel repository.

Sync the Project-Wisdom `17` local manifest with `repo sync --recurse-submodules` so PhhIms receives rnnoise, AEC3, and nested Abseil. If those submodules were not checked out, run `git -C packages/apps/PhhIms submodule update --init --recursive` from the Android tree; the pinned AEC3 commit can be fetched directly from its upstream by full SHA. From the patch repository root, check a clean synced tree and then apply:

```sh
python3 apply.py --check /path/to/derpfest17
python3 apply.py --apply /path/to/derpfest17
```

Use `--project packages/modules/Bluetooth` (repeatable) to limit the operation. `--apply` first checks every selected project, then applies the patches. Review the resulting diff and build before release. When upstream commits move, rebase each patch deliberately and update its base commit and checksum; do not force it onto an unrelated revision.

Run `--apply` only after `--check` succeeds on a clean synced workspace.
